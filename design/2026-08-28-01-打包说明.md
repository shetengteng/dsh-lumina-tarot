# 打包说明

> 日期：2026-08-28  
> 仓库：`dsh-lumina-tarot`  
> 依据：`package.json`、`scripts/build.mjs`、`cordis.patch.yml`、官方契约 https://dsh.pub/develop-plugin.md

本包是 **Host + Web UI** 双面插件：同一 npm 包、一次 `dsh plugin add`。运行入口是构建后的 `lib/`，不是 `src/`。

---

## 1. 打什么

| 产物 | 格式 | 入口 | 谁加载 |
|------|------|------|--------|
| `lib/index.js` | ESM（Node 20） | `exports["."]` / `main` | Host（`dsh web` 主进程） |
| `lib/client.js` | lazy-CJS | `exports["./client"]` | 浏览器，路径 `/plugins/dsh-lumina-tarot/client.js` |
| `lib/decks/` | webp 静态资源 | Host `webServer` 前缀 `/lumina-tarot/decks` | 卡面图；Client 只拼 URL |

`cordis.patch.yml` 只 insert **一行** Host（`id: lumina-tarot`，`name` 必须等于 `package.json` 的 `name`）。Client 由 `dsh.client.platform: "web"` 自动跟出，不要第二条安装命令。

`package.json` 的 `files` 决定发布物（Git 安装仍会拉整仓，再跑 `prepare`）：

```
lib/index.js
lib/client.js
lib/decks/
cordis.patch.yml
LICENSE
NOTICE
```

不要把 `src/` 当运行入口。`.gitignore` 不忽略 `lib/`：交付优先可复现的构建产物。

---

## 2. 怎么打

仓库根目录：

```sh
pnpm install
pnpm build
```

`build` 与 `prepare` 是同一条命令：`node scripts/build.mjs`。Git 安装会自动跑 `prepare`，本地开发改完代码后自己跑 `pnpm build`。

成功时终端应出现：

```text
built lib/index.js and lib/client.js
```

要看**可安装的 tarball**（按 `files` 打进 `output/`）：

```sh
pnpm pack:output
# 没有 pnpm 时：node scripts/pack.mjs
```

产物：

```
output/dsh-lumina-tarot-0.1.0.tgz   # 给 dsh plugin add 用
output/package/                     # 解压后的文件，方便核对
```

文件名里的版本来自 `package.json` 的 `version`。`output/` 已 gitignore，不进仓库。

**不是打包步骤**（不要和 `pnpm build` 混）：

| 命令 | 用途 |
|------|------|
| `pnpm export-domain` | 从 sibling `tt-lumina-tarot` 导出 `cards.json` / `spreads.json`。日常开发不需要。 |
| `pnpm e2e` | 真实 `dsh web` 端到端，假设插件已经装上。 |
| `pnpm verify:p6` / `verify:p7` | 阶段核对脚本，不产出交付包。 |

## 3. 构建脚本在做什么

`scripts/build.mjs` 分三步，全部写进 `lib/`。

### 3.1 Host

```
src/index.ts  →  esbuild  →  lib/index.js
```

- `format: esm`，`platform: node`，`target: node20`
- `packages: 'external'`：不把 `node_modules` 打进 Host
- 抽牌、tools、slash、settings schema、skill、牌面静态服务都在这一面

### 3.2 Client

```
src/client/index.ts  →  esbuild CJS  →  lib/_client.cjs  →  包一层 ModuleLoader  →  lib/client.js
```

中间文件 `_client.cjs` 写完即删，不进交付。

外层必须是 Harness Web 的 lazy-CJS 工厂（`id` 必须等于包名）：

```js
window.__ModuleLoader__.load({
  id: 'dsh-lumina-tarot',
  factory: (require) => { /* CJS 包体 */ return module.exports; },
});
```

约束：

- **不打包 React**。`external: ['react', 'react/jsx-runtime', '@deepseek-ai/dsh-client-ui-primitives']`，运行时 `require('react')`。
- JSX：`jsx: 'automatic'`（对应源码 `react-jsx`）。
- `.webp` 走 `dataurl`：仅对 **import 进 Client 源码** 的图生效（例如设置页预览的 fool.webp）。78 张牌面本身不打进 `client.js`。

核对产物：

```sh
rg -n "__ModuleLoader__" lib/client.js | head
```

应能看到 `id: 'dsh-lumina-tarot'`。不要把 ESM 源码直接拷成 `lib/client.js`。

### 3.3 牌面目录

```
src/client/decks/{rws,aquatic}/*.webp  →  原样拷贝  →  lib/decks/
```

Host 在 `src/host/deck-static.ts` 注册前缀 `/lumina-tarot/decks`。优先读构建后的 `lib/decks`，没有再回退到 `src/client/decks`。发布包必须带上 `lib/decks/`，否则韦特 / Aquatic 卡面会 404。

## 4. 打完怎么交给 DSH

### 4.1 本地开发（link 当前仓库）

```sh
pnpm build
dsh plugin --profile web add .
dsh --profile web --dump-config    # 应出现 # == dsh-lumina-tarot
dsh web
```

`add .` 是开发 link，仓库目录要一直在。改完 Client / Host 后重新 `pnpm build`，已装上的包通常要 **重启 `dsh web`，再刷新浏览器**。没有 HMR。

### 4.2 GitHub 安装（源码 + prepare）

```sh
dsh plugin --profile web add github:shetengteng/dsh-lumina-tarot
# 建议钉 commit，避免后续 push 悄悄改掉已装内容
dsh plugin --profile web add github:shetengteng/dsh-lumina-tarot#<40-character-commit>
```

Git 装的是源码，**不会**跑 `pnpm build` 这个名字，而是 npm 生命周期里的 `prepare`（内容相同）。pnpm 10 默认拦截 git 依赖的构建脚本；第一次失败时，按 CLI 提示把包名写进该 profile 的 `pnpm-workspace.yaml` 再重跑：

```yaml
allowBuilds:
  dsh-lumina-tarot: true
```

已装过的 GitHub 包要拉新代码，走官方 `dsh plugin`（转发 pnpm），不要自己写更新器：

```sh
dsh plugin --profile web update dsh-lumina-tarot
```

然后重启 `dsh web`。钉了 `#<commit>` 的 spec 不会跟着默认分支走。

### 4.3 tarball（预构建，无需 allowBuilds）

tgz 里已经带上 `lib/`，安装时**不会**再跑 `prepare`，也不需要 `allowBuilds`。适合发给别人试装，或核对自己打出来的包到底有没有缺文件。

**打 tgz**

```sh
pnpm pack:output
```

确认存在 `output/dsh-lumina-tarot-0.1.0.tgz`（版本号随 `package.json` 变）。

**装 tgz**

在仓库根目录（路径相对于你执行命令的 cwd）：

```sh
dsh plugin --profile web add ./output/dsh-lumina-tarot-0.1.0.tgz
dsh --profile web --dump-config    # 应出现 # == dsh-lumina-tarot
dsh web
```

若这个 profile 里已经用 `add .` 或 GitHub 装过同名包，先卸再装 tgz，避免还链着本地源码：

```sh
dsh plugin --profile web remove dsh-lumina-tarot
dsh plugin --profile web add ./output/dsh-lumina-tarot-0.1.0.tgz
```

把 tgz 拷到别的机器时，把路径换成实际位置即可，例如：

```sh
dsh plugin --profile web add /path/to/dsh-lumina-tarot-0.1.0.tgz
```

装的是这份压缩包里的内容，之后改仓库源码、重跑 `pnpm build` **不会**自动更新已装的 tgz 副本。要验新包：再打一次 `pnpm pack:output`，卸掉旧的，重新 `add` 新 tgz。

`npm pack` 还会带上 `README.md` / `README.en.md`（即使没写进 `files`）。缺 `lib/index.js`、`lib/client.js` 或 `lib/decks/` 就不要拿去 `add`。

当前未发 npm registry。Git / tgz 仍是主交付路径。官方建议独立 Git 插件 **提交** `lib/`，这样即使用户拦了 `prepare`，只要产物在仓里也能装。本仓 `.gitignore` 已按此处理。发 npm 见下一节。

### 4.4 发 npm（可以，但不是现在的主路径）

**可以发。** 包名 `dsh-lumina-tarot` 未占用 `@deepseek-ai` 官方 scope，也不是 `workspace:` 包。DSH 支持：

```sh
dsh plugin --profile web add dsh-lumina-tarot
dsh plugin --profile web add dsh-lumina-tarot@0.1.0
```

从 registry 装的是已经打好的 `lib/`，**不会**跑 `prepare`，也不需要 `allowBuilds`。这和装 tgz 同类。

发之前先想清楚这几条，再 `publish`：

| 项 | 现状 | 含义 |
|------|------|------|
| 包名 | 无 scope 的 `dsh-lumina-tarot` | 第一次发布即占名，改名必须同步改 `cordis.patch.yml` 的 `name` |
| 许可证 | 源码 MIT；Aquatic 牌面 CC BY-NC-SA 3.0 | 必须带着 `NOTICE`。不要把整包当纯 MIT 卖或做商业产品 |
| `esbuild` | 在 `dependencies` | Git 安装的 `prepare` 需要它。npm 用户也会多装一份，暂时可接受 |
| 体积 | 牌面约占 15 MB | 公开发布能过，但要比 Git 安装慢 |
| 元数据 | 还没有 `repository` / `author` | 建议发布前补上，方便 npm 页跳回 GitHub |

**不要**用 `@deepseek-ai/...`。若改成自己的 scope（例如 `@shetengteng/dsh-lumina-tarot`），`cordis.patch.yml` 的 `name` 必须改成完全相同的字符串，否则 Loader 解析不到包。

**发布步骤**

1. [npmjs.com](https://www.npmjs.com) 注册账号，本机登录：

```sh
npm login
npm whoami
```

2. 核对将要上传的内容（和装 tgz 是同一份）：

```sh
pnpm pack:output
# 看 output/package/：必须有 lib/index.js、lib/client.js、lib/decks/、cordis.patch.yml、NOTICE
```

3. 确认 `package.json` 的 `version`（当前 `0.1.0`）。已发过的版本不能覆盖，改版再发。

4. 在仓库根发布（会先跑 `prepare` 再上传 `files` 里的路径）：

```sh
npm publish
```

无 scope 默认就是 public。若以后改成 scope 包，要用 `npm publish --access public`。

5. 装刚发布的版本验一次（不要用 `add .`，那还是本地 link）：

```sh
dsh plugin --profile web remove dsh-lumina-tarot
dsh plugin --profile web add dsh-lumina-tarot@0.1.0
dsh --profile web --dump-config
dsh web
```

**改版**

```sh
# 改 package.json version，或：
npm version patch    # 0.1.0 → 0.1.1，会打 git tag
pnpm pack:output     # 再看一遍产物
npm publish
```

**没做的事不要声称已经发布。** 没有 `npm publish` 成功、没有在 npm 页面看到该版本之前，README / 落地页不要写 `dsh plugin add dsh-lumina-tarot` 当官方安装命令。现在对外仍用 GitHub 或 tgz。

## 5. 装上之后核对

分开声明：构建成功 ≠ 已安装 ≠ 已激活 ≠ UI 已加载。没跑过的检查不要声称通过。

```sh
dsh --profile web --dump-config
dsh web
```

| 检查 | 期望 |
|------|------|
| `dump-config` | 出现 `# == dsh-lumina-tarot` 层 |
| Host 终端 | `[lumina-tarot] host loaded` |
| 浏览器控制台（web profile） | `[lumina-tarot] client loaded` |
| 只执行一次 `add` | 没有第二条 Client 安装命令 |
| headless profile | 可以有 Host tools，没有悬浮牌背；这不代表 Client 已加载 |

卸载（两面一起卸，不清偏好和历史）：

```sh
dsh plugin --profile web remove dsh-lumina-tarot
```

## 6. 常见踩坑

- **改了 `src/` 却没 `pnpm build`**：DSH 读的是 `lib/`。Git 安装靠 `prepare`；本地 link 不会自动重打。
- **Client 打成 ESM / 没包 ModuleLoader**：壳按 classic script 拉 `client.js`，工厂对不上就加载失败。
- **把 React 打进 Client**：体积翻倍，且和壳的 React 实例冲突。
- **`cordis.patch.yml` 的 `name` 和 `package.json` 的 `name` 不一致**：行插进去但解析不到包。
- **`files` 漏了 `lib/decks/`**：设置里选韦特 / Aquatic 后牌面 404。
- **把 `workspace:` 依赖写进独立仓**：Git / pack 安装会解不出来。本包依赖只有 `esbuild`；Harness 运行时走 peer。
- **用 headless 验收 UI**：无界面 profile 装成功只证明 Host。
- **`export-domain` 当构建**：那是从旧 PWA 抽 JSON 的一次性脚本，缺 sibling 会失败，与交付包无关。
